# Data Contracts

The shared schemas every engineer and agent codes against. This is the doc that
makes integration-with-stubs possible.

> **Canonical source:** `harness/contracts.py` (Pydantic v2).
> **Mirror:** `src/contracts/index.ts` (hand-kept TypeScript, for the dashboard).
> **Stubs:** `data/stubs/*.json`, generated by `scripts/dump_stubs.py`.
>
> If the Python and the mirror disagree, **`contracts.py` wins** — and you must
> update the mirror + this doc in the same change (AGENTS.md non-negotiable #1).
> `python scripts/dump_stubs.py` (round-trip) and `pnpm typecheck` (stubs vs
> mirror) together keep all three honest.

## Superset merge (read this first)

These shapes are a **superset** reconciling Eng 1's lean Pydantic proposal with
Eng 4's already-built dashboard (DECISIONS.md D8):

- **Core fields** are render-ready and consumed by the dashboard today
  (embedded `concept`/`score`, the 8-dim `RewardDimensions`, `Lesson`,
  structured `HarnessDiff`, `element_weights`).
- **"Eng 1 additions"** are *optional* backend/short-form-video fields pending a
  prune once Eng 1 and Eng 4 align. Some are renames of a core field; the
  equivalence is noted inline in `contracts.py` (e.g. `pairwise_winprob` ≡
  `predicted_win_prob`, `system_prompt` ≡ `script_prompt`).

The Python side serializes stubs with `exclude_none=True`, so an unset optional
is simply absent from the JSON (and the TS mirror marks it `?`).

## Three vocabularies — do not conflate

| | What it is | Where it lives |
|---|---|---|
| **Rubric dimensions** | *How we score* a concept | `RewardScore.dimensions` (8 keys) → `docs/JUDGE_RUBRIC.md` |
| **Element weights** | *Generation biases* over content elements | `HarnessState.element_weights` (current) + `ContentConcept.element_weights` (per-concept inner-loop snapshot) |
| **Element taxonomy** | The *action space* the meta-agent can expand | `HarnessState.element_taxonomy` |

## The five contracts (+ two derived)

- **TrendContext** — what the world is doing.
- **ContentConcept** — what we propose to make.
- **RewardScore** — how the concept scored and why.
- **GenerationRecord** — the living-memory row for one generation (render-ready; embeds concept + score).
- **HarnessState** — the mutable scaffold: prompts, weights, taxonomy, policy, lineage.
- *(derived)* **HarnessDiff** — a proposed change to HarnessState (Meta-Agent output).
- *(derived)* **Lesson** — a distilled memory lesson (Wiki Curator output).

Condensed Pydantic (core fields shown; see `harness/contracts.py` for the full
models incl. the optional Eng 1 additions):

```python
class TrendContext(BaseModel):
    id: str; captured_at: datetime; platform: str; audience: str
    trend_summary: str; signals: list[TrendSignal] = []; source: str = "stub"
    # + Eng 1: trend_id, topic, hook, format, audio, region, source_urls, raw_signals

class ContentConcept(BaseModel):
    id: str; generation_number: int; trend_context_id: str; harness_state_version: str
    hook: str; format: str; angle: str; script: str; visual_prompt: str
    elements: list[str] = []; created_by: str = "content-generator"
    # + Eng 1: element_weights (inner-loop snapshot), storyboard, seedance_prompt, duration_sec, ...

class RewardDimensions(BaseModel):   # keys == docs/JUDGE_RUBRIC.md; risk dims higher = worse
    hook_strength: float; trend_fit: float; brand_fit: float; novelty: float
    clarity: float; cringe_risk: float; policy_risk: float; visual_feasibility: float

class RewardScore(BaseModel):
    id: str; concept_id: str; generation_number: int; harness_state_version: str
    dimensions: RewardDimensions; weighted_total: float
    predicted_win_prob: float | None = None; policy_flag: bool = False; judge_rationale: str
    # + Eng 1: predicted_score, pairwise_winprob, confidence, scored_by, rationale, scored_at

class HarnessState(BaseModel):
    id: str; version: str; element_weights: dict; script_prompt: str
    seedance_prompt_template: str; judge_rubric: str; policy_rules: list[str] = []
    updated_from_generation_id: str | None = None
    # + Eng 1: element_taxonomy, system_prompt, tools, few_shot_examples,
    #          rubric_version, parent_harness_id, diff_summary, generation

class HarnessDiff(BaseModel):
    id: str; from_version: str; to_version: str; element_weight_changes: dict
    script_prompt_change: str | None = None; rationale: str; accepted: bool
    # + seedance_prompt_template_change, judge_rubric_change, policy_rule_changes

class Lesson(BaseModel):
    id: str; generation_number: int
    observation: str; rule: str; evidence: str; harness_change: str; expected_effect: str

class GenerationRecord(BaseModel):   # render-ready: embeds concept + score
    id: str; generation_number: int; created_at: datetime; trend_context_id: str
    concept: ContentConcept; score: RewardScore
    harness_state_version_before: str; harness_state_version_after: str | None = None
    harness_diff: HarnessDiff | None = None; lesson: Lesson | None = None
    # + Eng 1: harness_id, predicted_score, actual_engagement, post_url, selected, rubric_version, diff_summary, ...
```

## Conventions

- Timestamps are UTC, ISO-8601 on the wire (`datetime` ↔ string).
- Persist with `.model_dump_json()`; load with `.model_validate_json()`.
- Stubs are written with `exclude_none=True` (unset optionals omitted).
- Storage is plain JSON files today (the loop writes them; the dashboard reads
  them via `src/ui/lib/data.ts`). Redis is a WeaveHacks stretch.
